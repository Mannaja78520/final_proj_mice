แยกชุดเต้นอัตโนมัติ: ค่าเริ่มต้น Automatic ตรวจคนหลายคนและการเปลี่ยนมุมกล้องในคลิปใหม่เอง เมื่อใช้ Automatic หรือ Group dance ระบบเปรียบเทียบการเคลื่อนไหวตลอดคลิปใหม่ทุกครั้ง ไม่กำหนดตำแหน่งชาย/หญิงไว้ล่วงหน้า คนที่แขนเหมือนกันแต่บิดเอวหรือเอียงไหล่ต่างกันอาจอยู่คนละชุดท่า เลือก Dance routine เพื่อดูแต่ละชุด หรือ Save separate routines เพื่อบันทึกชุดที่มีหลักฐานแตกต่างต่อเนื่องและมีภาพเชื่อถือได้ผ่านสัดส่วนภาพที่กำหนดในค่าตั้งต้นเป็นโครงการแยก ส่วน Fragment คือช่วงที่ยังยืนยันว่าเป็นชุดท่าใหม่ไม่ได้ เก็บไว้ดูและบันทึกทีละชุดได้ ไม่ถือว่าเป็นชุดเต้นใหม่ทุกครั้งที่กล้องตัด หากมุมใหม่จับคู่ชุดเดิมไม่ได้ชัดเจน ระบบใช้ข้อมูลภาพของผู้เต้นร่วมกับการจับคู่ทุกกลุ่มพร้อมกัน และทำเครื่องหมาย check cut เมื่อการจับคู่ยังคลุมเครือ การจับคู่มุมใหม่ที่ยังคลุมเครือจะคงท่า ไม่เปลี่ยนเป็นเชื่อถือได้เพียงเพราะรอครบเวลา หากหลายคนที่เห็นในภาพนั้นทำท่าเดียวกันจริงจึงใช้ท่าร่วมที่ยืนยันได้ รายงาน % reliable คือสัดส่วนภาพที่ใช้ได้ ไม่ใช่การรับรองว่าเป็นบุคคลเดิมแน่นอน ผู้ใช้เลือกคนเองได้เป็นทางเลือก

ภาพตัดที่จับคู่คนเดิมไม่ได้: ระบบแยกเป็น Scene segment อัตโนมัติ เลือกผู้เต้นหลักที่เห็นต่อเนื่องในชุดท่านั้น ไม่สลับตามค่าความมั่นใจทุกภาพ ช่วงวิดีโอและเวลาท่าของแต่ละส่วนเริ่มตรงกัน เมื่อแก้ช่วงวิดีโอจะยกเลิกการอ่านเดิมและให้วิเคราะห์ช่วงใหม่ โดยไม่เติมการยืนนิ่งยาวก่อนช่วงที่มองเห็น Make and save จะบันทึกชุดหรือช่วงที่ผ่านเกณฑ์แยกกัน ไม่สร้างโชว์ที่เดาว่าคนละท่าเป็นคนเดียวกัน การจับคู่ข้ามกล้องที่คลุมเครือยังไม่ใช่การรับรองเพศหรือบุคคลเดิม

เต้นต่อเนื่อง: ค่าเริ่มต้นรักษารูปท่าและเพิ่มเวลาตามขีดจำกัดหุ่น หากต้องการจังหวะเพลงเดิมให้เลือก Stay with the music ซึ่งอาจลดระยะเคลื่อนไหว ระบบกรองการสั่นตามเวลา ลดการกลับทิศสั้นและการเปลี่ยนมุมข้อต่อฉับพลัน เมื่อคนหยุดนิ่งหลังเปลี่ยนท่า หุ่นยังเคลื่อนให้ถึงท่าที่รับไว้ก่อนค้าง ไม่หยุดกลางทางจากตัวกรอง ยังคงท่าเปิดและช่วงยืนนิ่ง ไม่ดึงท่าจากอนาคตมาเติมภาพที่มองไม่เห็น หลังกรองจะตรวจการชนและเวลาใหม่และแสดงจำนวนการกลับทิศก่อน/หลัง ภาพต้นฉบับและรายงานความคลาดยังใช้ตรวจว่าการกรองกินรายละเอียดท่าเกินไปหรือไม่ ริกและขอบเขตมอเตอร์อาจทำให้บางท่ายังต่างจากคน

ตามวิดีโอคนเดียวหรือเต้นหมู่

ช่วงอ้อมที่ช้ากว่าความเร็วต่ำสุดของตัวเล่นวิดีโอจะเลื่อนภาพตามนาฬิกาหุ่นทีละภาพ โดยเสียงหยุดชั่วคราว ใช้ Play both เพื่อหยุดหรือเล่นต่อ การเปลี่ยนวิดีโอหรือโหมดจะคืนความเร็วปกติและยกเลิกการอ่านเดิมทันที เพลงต้นฉบับจะไม่ถูกส่งไปผูกกับชุดท่าที่ถูกยืดเวลา เพราะจะคลาดจังหวะ ต้องใช้ไฟล์เพลงที่ปรับเวลาแล้ว สำหรับชุดเชียร์ที่จัดให้มีไฟล์เพลงปรับเวลามาคู่กัน

หน้า Video เลือก Performers เป็น One performer หรือ Group dance และเลือก Camera เป็น One camera view หรือ Changing shots / viewpoints แยกกันได้ หลังอ่านคลิปจะมีเลขผู้เต้นให้เลือกที่ Follow ชุดท่าที่ต่างกัน เช่นท่าของผู้เต้นชายและหญิง จะไม่ถูกเฉลี่ยรวมกัน ตรวจและบันทึกแต่ละคนหรือแต่ละชุดแยกชื่อ

Turn the waist ใช้มุมลำตัวสัมพันธ์กับสะโพก ส่วน Follow shoulder tilt ใช้มุมไหล่สัมพันธ์กับลำตัว ผ่านการเทียบกับกลไกจริงในริก คนที่ยืนนิ่งจะไม่ดึงท่าอนาคตมาเติม และไม่เกลี่ยข้ามภาพตัด กล้องด้านข้างหรือมุมสูงจะตรวจในกรอบลำตัวก่อนรับท่าใหม่

Learned camera checks ใช้นโยบาย Q-learning ที่ฝึกในตัวจำลองช่วยตัดสินใจรับท่า เก็บท่าเดิม หรือชดเชยมุมมอง เปรียบเทียบกับวิธีเรขาคณิตก่อนเปิดใช้ ถ้าถูกบัง ไม่แน่ใจว่าเป็นคนเดิม หรือแยกการหมุนคนกับกล้องไม่ได้ จะเก็บท่าที่เชื่อถือได้ล่าสุด ผลตัวจำลองไม่ได้ยืนยันความแม่นยำบนคลิปจริง

ตรวจแผ่นมือ ลูกบอลข้อต่อ ก้านแขน ลำตัว และศีรษะตามท่าจริง รวมการยกไหล่ ทุกชิ้นต้องห่างกันอย่างน้อย 10 มม. (เผื่อระยะคลอนของเฟืองเซอร์โว ตั้งได้ใน safe_path.json ค่า clearMm บวกระยะเผื่อของ rig) ท่าปลายทางที่ชนจะหาท่าใกล้เคียงที่ว่างก่อน แล้วใช้ RRT* หาเส้นทางอ้อม ตรวจหลังปัดมุมและปรับเวลาอีกครั้ง พรีวิว โปรเจกต์ และชุดคำสั่งส่งออกใช้ชุดท่าที่ตรวจแล้วเดียวกัน Stay with the music อาจลดระยะขยับเมื่อหุ่นตามไม่ทัน หากปิดจะรักษาท่าและเพิ่มเวลาให้ขยับหรืออ้อม โดยวิดีโอพรีวิวช้าลงตามจังหวะหุ่น การเกิดท่าซ้ำไม่ยุบหรือย้อนเวลาเพลง

1 สไลเดอร์แขนซ้าย (L_SH_P, L_SH_R, L_EL_P, L_EL_R)
ปรับอย่างไร: ลากสไลเดอร์หรือพิมพ์องศา (ช่วงที่ตั้งไว้สำหรับข้อนั้น; HOME และจุดศูนย์อาจต่างกัน)
หุ่นยนต์เปลี่ยนไปยังไง: • L_SH_P / L_SH_R: ไหล่ซ้ายก้ม-เงย (Pitch) และกางออก-หุบเข้า (Roll)
• L_EL_P / L_EL_R: ข้อศอกซ้ายงอพับและหมุนบิดท่อนแขน
เซอร์โวหมุนตามองศาจริงทันที พร้อมระบบจำกัดขอบเขตไม่ให้ชนโครงหุ่น
2 สไลเดอร์แขนขวา (R_SH_P, R_SH_R, R_EL_P, R_EL_R)
ปรับอย่างไร: ลากสไลเดอร์หรือกดปุ่ม Mirror เพื่อคัดลอกท่าจากแขนซ้าย
หุ่นยนต์เปลี่ยนไปยังไง: คุมแขนขวา 4 แกนอิสระ หากกด Mirror แขนขวาจะกางทำท่าสมมาตรกับแขนซ้ายทันที เหมาะสำหรับทำท่าไหว้ ท่ากอดอก หรือท่ายกมือพร้อมกัน
3 สไลเดอร์เอวและยักไหล่ (WAIST & SHRUG)
ปรับอย่างไร: WAIST ปรับหมุนซ้าย-ขวา / SHRUG ปรับโครงสร้าง 4-Bar Linkage
หุ่นยนต์เปลี่ยนไปยังไง: • WAIST: เอวเอี้ยวตัวมองไปด้านข้างได้ ±30°
• SHRUG: คานไหล่เอียงยกข้างหนึ่งขึ้น อีกข้างหนึ่งลง รวม 26° เลียนแบบการยักไหล่ของมนุษย์
4 ปุ่มลัดความปลอดภัย (Home / Relax / Zero Lock)
ปรับอย่างไร: คลิกปุ่ม Home, Relax หรือ Zero Lock ด้านล่าง
หุ่นยนต์เปลี่ยนไปยังไง: • Home: กลับท่า HOME ที่ตั้งไว้ องศาแต่ละข้ออาจไม่ใช่ 90°; ตรวจท่าจริงและค่าที่บันทึกไว้
• Relax: หยุดส่งพัลส์ควบคุมเซอร์โว; ไม่ได้ตัดไฟเลี้ยง และการคลายแรงยึดขึ้นกับเซอร์โว
• Zero Lock: ล็อคพิกัดจุดศูนย์ ป้องกันคนกดเลื่อนตำแหน่งโดยไม่ตั้งใจ

หุ่นยนต์เปลี่ยนไปยังไง: แก้ปัญหาเขาสวมเซอร์โวขบฟันเฟืองไม่ตรงตำแหน่ง ช่วยให้แขนตรงสนิทโดยค่าที่ชดเชยจะถูกบันทึกลงหน่วยความจำ NVS บนตัวหุ่นยนต์ ไม่สูญหายเมื่อปิดสวิตช์
2 ลิมิตความปลอดภัย (Joint Safety Limits)
ปรับอย่างไร: ระบุค่า Min (เช่น 15°) และ Max (เช่น 165°) ของแต่ละข้อต่อ
หุ่นยนต์เปลี่ยนไปยังไง: ตัวหุ่นจริงและ Studio จะไม่ยอมหมุนเกินพิกัดนี้เด็ดขาด ป้องกันแขนพับชนลำตัวหรือเซอร์โวติดขัดจนไฟตก (Brownout Guard)
3 ตารางแคลิเบรตยักไหล่ (4-Bar Shrug Curve)
ปรับอย่างไร: ป้อนระยะยกจริง (mm) เทียบกับองศาเซอร์โวยักไหล่
หุ่นยนต์เปลี่ยนไปยังไง: คานยักไหล่จะขยับตามกลศาสตร์คณิตศาสตร์ของ 4-Bar Linkage จริง หัวไหล่ยกขึ้นได้อย่างสมจริงเป็นธรรมชาติ

1 ไฟล์ท่าทาง (YAML Sequence Files)
ปรับอย่างไร: เลือกไฟล์จากดรอปดาวน์ Open saved YAML… หรือกด Save
หุ่นยนต์เปลี่ยนไปยังไง: โหลดชุดท่าทางที่เคยออกแบบไว้กลับเข้าสู่เส้นเวลาเพื่อแก้ไข หรือส่งไฟล์ขึ้นการ์ด SD ของหุ่นยนต์
2 ตัวคูณความเร็ว (Sequence Speed Multiplier)
ปรับอย่างไร: ปรับสปีด 0.5x, 1.0x, หรือ 1.5x
หุ่นยนต์เปลี่ยนไปยังไง: เร่งหรือหน่วงการเคลื่อนไหวทั้งชุดท่าทางให้เร็วขึ้นหรือช้าลงตามต้องการ โดยคงอัตราส่วนจังหวะเดิมไว้ครบถ้วน
3 การร้อยท่าทางอัตโนมัติ (Sequence Chain)
ปรับอย่างไร: ใส่ชื่อไฟล์ถัดไปในช่อง Chain เช่น wave.yaml
หุ่นยนต์เปลี่ยนไปยังไง: เมื่อหุ่นเล่นท่าปัจจุบันจบ จะเริ่มเล่นท่าต่อไปทันทีโดยไม่ต้องส่งคำสั่งใหม่ ทำให้จัดโชว์ยาวๆ ได้อย่างต่อเนื่อง
4 ความเร็วตอนเต้นตามเพลง (Speed limit with music)
ปรับอย่างไร: ในการ์ด Timing ช่อง Speed limit with music (ขึ้นเฉพาะชุดท่าที่มีเพลง) ใส่ °/วินาที ปล่อยว่าง = ใช้ค่าของหุ่น, 0 = เร็วสุดเท่าที่เซอร์โวไหว ใต้ช่องจะบอกว่าท่าไหนตามเพลงไม่ทันและช้ากว่าเพลงกี่วินาที กดชื่อท่าเพื่อไปแก้ ตัด หรือเปลี่ยนท่านั้น
หุ่นยนต์เปลี่ยนไปยังไง: ใช้เฉพาะชุดท่านี้ตอนเพลงเล่นเท่านั้น (ไฟล์เขียน pace: music N หุ่นรับเป็น PACE MUSIC N) จบเพลง กด STOP หรือเปิดเครื่องใหม่ หุ่นกลับไปใช้ Peak speed limit เดิม (60 °/วินาที) ทุกครั้ง ตรวจการชน ขอบเขตข้อต่อ และระยะห่างมือยังทำงานที่ความเร็วใหม่ ลองกับหุ่นจริงให้เริ่มจากค่าต่ำแล้วค่อยเพิ่ม
5 ดูว่าเซอร์โวจริงตามทันไหม (Play like the real servos)
ปรับอย่างไร: ติ๊ก Play like the real servos ในการ์ด Timing แล้วกด Play หุ่นในภาพจะขยับช้ากว่าแผนแบบเซอร์โวจริง ท่าที่เซอร์โวตามไม่ทันมีขอบเส้นประบนแถบเวลา (เหลือง = ช้าเล็กน้อย, แดง = ช้ามาก) ค่าความหน่วงและการเร่งของแต่ละข้อปรับได้ใน Setup > rig (delay ms, speed-up °/s²)
หุ่นยนต์เปลี่ยนไปยังไง: ไม่เปลี่ยนหุ่น เป็นภาพตรวจในจอเท่านั้น ค่าความหน่วงยังเป็นค่าประมาณจนกว่าจะวัดกับหุ่นจริง ตัวจำลองฟิสิกส์ (tools/nong_sim) ใช้ค่าชุดเดียวกัน

1 ผูกเพลงประกอบ (Show Music Sync)
ปรับอย่างไร: เลือกไฟล์เพลงจาก /music/song.mp3 ในการ์ด SD
หุ่นยนต์เปลี่ยนไปยังไง: เสียงเพลงและท่าทางของหุ่นยนต์จะเริ่มเล่นพร้อมกันอย่างตรงจังหวะ และระบบจะปิดเสียงอัตโนมัติเมื่อกด Stop
2 จุดพักหยุดรอ (Pause Intervals)
ปรับอย่างไร: กำหนดเวลาหยุดพักระหว่างท่า เช่น pause: 2.0s
หุ่นยนต์เปลี่ยนไปยังไง: หุ่นยนต์จะหยุดค้างท่าทางสวยงามตามเวลาที่กำหนด ก่อนจะเริ่มเล่นท่าถัดไป
3 ส่งโชว์เข้าบอร์ด (Save to robot)
ปรับอย่างไร: กดปุ่ม 💾 Save to robot
หุ่นยนต์เปลี่ยนไปยังไง: โชว์จะถูกบันทึกลงในการ์ด SD ของตัวหุ่น ทำให้หุ่นยนต์สามารถเปิดเครื่องและแสดงโชว์ได้ด้วยตนเองโดยไม่ต้องต่อคอมพิวเตอร์
จุดที่ 7: แขนขยับตอนพูด (Moves while talking) Sequence
1 ลองประโยค (▶ Show)
ปรับอย่างไร: พิมพ์ประโยคที่หุ่นจะพูด เลือกสไตล์การพูด (friendly, polite, …) แล้วกด ▶ Show
หุ่นยนต์เปลี่ยนไปยังไง: หน้านี้พูดประโยคด้วยเสียงเดียวกับหน้า Voice และแขนในภาพ 3D ขยับพร้อมเสียง เป็นการดูตัวอย่างเท่านั้น ตัวหุ่นจริงไม่ขยับ ท่าจะอยู่บน time bar ต่อ กด Play ดูซ้ำได้ (ไม่มีเสียง) ถ้ายังไม่ได้ล็อกอิน จะเห็นแค่ท่าโดยไม่มีเสียง ประโยคสั้นแค่ไหนก็ได้ท่าอย่างน้อยหนึ่งท่า
2 ท่าใหม่สำหรับคำที่ยังไม่มีท่า
ปรับอย่างไร: พิมพ์คำบอกทิศหรือส่วนของร่างกาย เช่น "ด้านขวาครับ", "ข้างบน", "หัวใจ" แล้วกด Show ติ๊ก Ask the AI for new moves ถ้าอยากให้ AI ตัวเดียวกับหน้า Voice คิดท่าให้ เมื่อไม่มีกฎไหนเข้า (ต้องล็อกอิน)
หุ่นยนต์เปลี่ยนไปยังไง: ท่าที่สร้างขึ้นจะถูกปรับตามขนาดหุ่น ลิมิตข้อต่อ และเช็กไม่ให้ชนตัวเอง (หาทางอ้อมถ้าจำเป็น) ท่าที่ทำให้ปลอดภัยไม่ได้จะบอกเหตุผลและไม่ถูกใช้ กด ＋ Keep เพื่อเก็บเป็นท่าถาวร แล้วหน้า Voice จะใช้ท่านี้กับคำนั้น คำและกฎทั้งหมดอยู่ใน config/gesture_makers.json
3 ท่าพักแขน (Hands between gestures)
ปรับอย่างไร: เลือก Hands ready (ศอกงอ มืออยู่หน้าตัว) หรือ Standing straight (Home) (ยืนตรงแขนลง)
หุ่นยนต์เปลี่ยนไปยังไง: ระหว่างท่าตอนพูด แขนจะกลับมาพักที่ท่านี้ แบบพร้อมขยับได้ไวกว่า แบบยืนตรงดูนิ่งกว่า
4 รายการท่าและ Events
ปรับอย่างไร: แก้คำที่เรียกแต่ละท่า กด ▶ ดูท่าเดียว หรือจัดท่าเองบน time bar แล้วกด ＋ Keep as a gesture ติ๊ก Events ออกเพื่อปิดท่าใน event นั้น
หุ่นยนต์เปลี่ยนไปยังไง: หน้า Voice เลือกท่าตามคำที่พูด และเติมท่าเล็ก ๆ แบบสุ่มในช่องว่าง

ภาพ 3D หยุดวาดเมื่ออยู่นิ่ง และวาดใหม่เมื่อท่าจากตัวแก้ไขหรือ Monitor เปลี่ยน เมื่อเปิด/ปิดกริดหรือเครื่องหมายมือ โหลดโมเดลเพิ่ม หรือปรับขนาดหน้าจอ

ถ้าอ่านรายการโปรเจกต์ที่บันทึกไว้ไม่ได้ Studio จะเก็บตัวเลือกเดิมและแจ้งข้อผิดพลาดทั้งแถบสถานะและแถบแจ้งเตือนกลาง จึงเห็นได้จากทุกแท็บ กด Retry saved moves เพื่อลองอ่านอีกครั้ง งานในหน้ายังคงอยู่

Robot pose training pictures (PC experiment)

Generate pose views with python -m tools.robot_pose synth --n 20000 --no-images --out ABSOLUTE_PRIVATE_PATH, then render python -m tools.robot_pose.render_mujoco ABSOLUTE_PRIVATE_PATH/views.jsonl --out ABSOLUTE_PRIVATE_PATH. MuJoCo uses the Studio rig and the saved camera, random light, colour, textures, blur and noise. Labels mark keypoints hidden by another part using depth. Joint centres inside their own housing use a rig-sized tolerance. Keep all pictures, labels and reports in the PC private .local/robot_pose folder using absolute paths. These are simulated images; real video labels still need independent hold observations and visual review. CAD appearance is optional when the private meshes exist; it follows the shared rig, with source attachment offsets checked. Landmarks absent from the CAD, including its virtual base point, stay unlabelled. Training views need at least three visible joints; fully hidden views are dropped. An unlabelled base point can still bound the robot post. No training, camera capture or robot commands run from this tool.

For recorded still frames, python -m tools.robot_pose.lab_labels ABSOLUTE_MANIFEST.json --out ABSOLUTE_PRIVATE_DATASET fits a camera from independently measured joint centres and known holds. The private manifest selects settled windows, validated landmarks, robot bounds, video-level train/validation splits and observed pose acceptance. A command acknowledgement alone does not prove the robot reached the pose: moving or visibly wrong frames are dropped. Only validated landmarks receive labels. Review at least 50 frame overlays before training; a single planar pose does not establish metric camera calibration.
