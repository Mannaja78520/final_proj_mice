served by the board — and by the hub over USB/RS485

Module website

One site per module, identical over every transport. The hub serves the board's own HTML with a transport shim, so a board with no WiFi shows the same page over a cable.

Three tabs, not one long pagenew

Control (the module's own controls), Sequences & files (run a sequence, the SD card, the console) and Setup (login, settings, pins, calibration). Thirteen cards in one column meant scrolling past the arm controls to reach the SD card.

The Setup cards still stay hidden until you log in — one rule decides both which tab a card is on and whether you may see it, so the two can never disagree.

Controls match the real board

Control cards render from the board's actual type — a nong board shows only nong controls, a lift only lift. No login needed to drive the robot.

Cards

Modules on network · Lift · RGB Strip · Speaker · Nong Arms · Zero position · Camera · Servo type · Sequences · Hardware pins · SD Files · Settings · Console.

Setup gate

A login hides the configuration cards — Settings, Hardware pins, Zero calibration, Servo type. Once in, you can add users, delete them and change your password.

Pin picker with a pinout drawing

GPIO dropdowns per function, with sub-tabs per module type inside the card and a ● marking the board's real type. The hub injects an ESP32 pinout SVG served from the PC, keeping it off the board's flash.

Sequences & files

List /moves, run any sequence, upload, download and delete SD files — over WiFi, USB or RS485 alike.
