Mice Hub — the PC app

The first page you open. Finds every module by itself and links to each one's website and to Nong Studio. Stdlib Python only; ships as a single exe.

Finds modules on its own

Parallel scan of the whole local subnet, plus every COM port on the PC. Bluetooth phantom ports are recognised from the device type and skipped instead of being probed — they hang for ~40 s if opened.

Streaming USB probe

One request per port, so each slot fills the moment that port answers and fast ports never wait for slow ones. Identifies the module plugged in directly and every module on the RS485 bus behind it.

One cable, many pagesfixed

The hub owns each COM port and shares it, so the module website and Nong Studio can drive one cable at the same time instead of colliding with "serial already in use". Commands are atomic on the wire, so replies never interleave.

Recovers from a replugged boardfixed

After a board is unplugged or reset, Windows leaves the handle looking open and every write fails. The hub detects the stale handle, drops it and reopens — no restart.

Serves the module site over any transport

/mod?dev=wifi:<ip> or usb:<port>[:<id>]. A unified device API routes commands, status, file listing, upload, download and delete to HTTP or serial as needed.

Hosts Nong Studio

Studio lives at /studio/, with "Studio + monitor" opening it already connected to a discovered nong. Also serves the RGB page and the pinout reference.

Adding a tool costs one foldernew

Every web app is a folder in code/apps/ with an app.json naming it. The hub lists it on the main page and serves it at /app/<name>/ — no route to add, no button to hand-write. Nong Studio and this help page are registry entries pointing at where they already live, so no link changed.

The manifests are JSON that allows // comments and trailing commas, so they are comfortable to edit by hand.

Sending the rig is 5x fewer commandsnew

Send rig to robot used to push five commands per joint — fifty round trips, about 1.6 s. The new JCFG command carries a joint's whole setup in one line, so it is ten. Only joints that actually differ are sent at all, and a board older than JCFG automatically gets the individual commands instead.

The board says what it can donew

Each module reports its capabilities in its status — motion, rgb, audio, joints, servos, sd, rs485 and so on — and the module website shows each card by capability rather than by module type. A new module type therefore shows the right controls without the site being taught about it. A board running older firmware sends no capabilities and still renders correctly.

Commands declared oncenew

firmware/config/commands.json declares every command — which module type it belongs to, its arguments and a one-line explanation. The board compiles it into a table for its own HELP, and QC checks it both ways: a declared command must have a handler, and a handler must be declared. It found two commands (PINS, PINS?) that had existed undocumented.

One servo table, shared by everythingnew

firmware/config/servos.json describes every servo preset once. The firmware compiles it into a header at build time — the chip parses nothing and pays nothing — and Nong Studio fetches the same file for its dropdown. They used to be two hand-kept copies that could drift apart with nothing to notice; QC now fails if they ever disagree.

Reachable from other devices

Binds all interfaces, so phones and laptops on the same WiFi can open the hub and every module page through it.

This help page, offlinenew

Served from the PC at /help — no internet, no account. Linked from Tools on the hub's main page, and searchable with the filter at the top.

Works on any screennew

The hub, the module website, Nong Studio and this page all lay out for phones, tablets and large monitors, with bigger touch targets on a touchscreen. Studio stacks the 3D view above its panel below 860px instead of squeezing both, and on a phone its view buttons (Top, Front, 3D…) fold behind one Views ▾ button.
