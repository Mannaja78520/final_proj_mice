最新の作品を動きと音楽つきで開く

ハブのホームには次のアプリがあります： 最新の作品 インストール済みの作品用です。まだ一覧がない PC はファイルを直接取り込めます。Nong Studio で次を押します： 音楽付きの作品を開く 次に、クリップまたはファイルを選びます .nong.json モーション、リグ（rig）、音楽を1つのファイルにまとめて保存します。プロジェクトを切り替える前に、システムがファイルを読み込んでチェックします。未保存の作業がある場合は、先に Save（保存）するかキャンセルするかを確認し、プロジェクトのリグを使うか現在の設定を維持するかを選択できます。異なるリグを使用すると、新しい制限に合わせてポーズやタイミングが変わる場合があります。

押すと 音楽付きで試す で、元の音楽と一緒に画面で動きを確認できます。一時停止、最初に戻る、タイムバーの移動もできます。音楽がプレビューの時計になっているので、タブが遅くなっても動きとずれません。音楽が動きより先に終わると残りは無音で、ループでは動きが終わったときに音楽も最初から始まります。作品を開いたりこのプレビューを使ったりしても、実際のロボットには何も送られません。「ロボットで実行」ボタンは別の手順です。

保存 音楽もプロジェクトに保存されるので、開き直してもそのまま残ります。または次を押して： 動き＋音楽をダウンロード 1 つのファイルを別の PC に移せます。下書きの音楽はブラウザー内に別に保存されるので、その保存領域が閉じられたり消されたりすると、元のファイルをもう一度選ぶ必要があるかもしれません（復元した動きは残っています）。実際のロボットには、play: コマンドと同じ名前の YAML ファイルと MP3 を SD カードに従来の方法でアップロードします。システムが自動でアップロードしたり再生させたりすることはありません。

プロジェクト名にはタイ文字・英字・数字・スペース・_ - . が使えます。絵文字、/ \ :、Windows の予約名（con、nul、com1 など）は使えません。わかりやすい言葉で知らせ、保存済みの内容は上書きしません。

3D を描けない端末（テレビ、古い PC、グラフィックカードを無効にしたブラウザー）： Studio は開いて使えます。スライダー、タイムライン、ロボットでの再生は普通に動き、3D のロボット表示だけは、この端末では描けないというメッセージになります。ロボットを見たいときは、新しいブラウザーか別の PC で開いてください。

ダンスの自動分離： 既定の「自動」は、新しいクリップで複数の人やカメラの角度の変化を自分で検出します。「自動」や「グループダンス」では、システムは毎回クリップ全体の動きを比べ、男女の位置を前もって決めることはしません。腕は同じでも腰のひねりや肩の傾きが違う人は、別の振り付けに入ることがあります。「振り付け」で各ルーチンを見るか、「ダンス / シーンを別々に保存」で、証拠が連続して異なり、初期値で決めた映像の比率を満たす信頼できる映像のルーチンを別プロジェクトとして保存します。「フラグメント」は新しい振り付けとはまだ確認できない区間で、1 つずつ見て保存でき、カメラが切り替わるたびに新しい振り付けとは数えません。新しい角度が以前のルーチンとはっきり対応づけられないときは、ダンサーの見た目とすべてのグループの同時照合を使い、まだ曖昧なら check cut の印を付けます。曖昧なままの新しい角度はポーズを保ち、時間が経っただけで信頼できるものにはなりません。その映像で見えた複数の人が本当に同じポーズをしているときだけ、確認済みの共通ポーズが使われます。「% reliable」は使える映像の割合で、同じ人であることの保証ではありません。ユーザーが自分で人を選ぶこともできます。

同じ人に対応づけられないカット： システムは自動でシーン区間に分け、そのルーチンで連続して見える主役のダンサーを選びます。映像ごとの信頼度で入れ替わることはありません。各部分の映像範囲と動きのタイミングは揃って始まります。映像範囲を編集すると、以前の読み取りは取り消されて新しい範囲が解析され、見える区間の前に長い静止が足されることはありません。「作って保存」は基準を満たしたルーチンや範囲を別々に保存し、別の動きを同じ人だと推測したショーは作りません。曖昧なカメラ間の照合は、性別や同一人物の保証ではありません。

続けて踊る： 既定では、ポーズの形を保ち、ロボットの限界に合わせて時間を足します。元の音楽のビートを保ちたいときは「音楽に合わせる」を選びますが、動きの幅が小さくなることがあります。システムは時間方向に細かい揺れをフィルターし、短い反転や関節角の急な変化を減らします。人がポーズを変えた後に止まっても、ロボットは止まる前に受け入れたポーズまで動き、フィルターのせいで途中で止まることはありません。最初のポーズと静止区間は保たれ、見えない映像を埋めるために未来のポーズを持ってくることもありません。フィルターの後に衝突とタイミングを再確認し、前後の反転回数を表示します。元の映像と誤差レポートは、フィルターがポーズの細部を削りすぎていないかの確認にも使われます。リグやモーターの範囲のため、一部のポーズは人とまだ違うことがあります。

1 人の動画やグループダンスに追従する

映像プレーヤーの最低速度より遅い迂回の区間は、ロボットの時計に合わせて映像を 1 コマずつ進め、音は一時停止します。「人とロボットを一緒に再生」で止めたり再開したりします。映像やモードを変えると、通常の速度に戻り、前の読み取りもすぐに取り消されます。元の音楽は、時間が引き延ばされたシーケンスに付けて送られません。拍がずれるためで、時間調整済みの音楽ファイルが必要です。応援のシーケンスには、時間調整済みの音楽ファイルが組になって用意されています。

動画のページで、パフォーマーを「1 人のパフォーマー」か「グループダンス」に、カメラを「1 つのカメラ視点」か「カット切り替え / 視点」に、別々に選べます。クリップを読み取ると、「追従」で選べるパフォーマーの番号が出ます。男性と女性のダンサーのように違う振り付けは、平均されて混ざりません。人ごと、ルーチンごとに確認し、それぞれ別の名前で保存してください。

「腰をひねる」は腰に対する胴体の角度、「肩の傾きに追従」は胴体に対する肩の角度を使い、リグ内の実際の機構と突き合わせます。静止している人のために未来のポーズを持ってきて埋めることはなく、カットをまたいで滑らかにすることもありません。横や真上のカメラは、新しいポーズを受け入れる前に胴体のフレーム内で確認されます。

「学習済みカメラチェック」は、シミュレーターで訓練した Q 学習のポリシーを使って、ポーズを受け入れるか、前のポーズを保つか、視点を補正するかの判断を助けます。オンにする前に幾何学的な方法と比較します。人が隠れている、同じ人か確かでない、人の回転とカメラの回転を分けられないときは、最後の信頼できるポーズを保ちます。シミュレーターの結果は、実際のクリップでの精度を保証するものではありません。

手のプレート、関節のボール、腕のロッド、胴体、頭を実際のポーズに合わせて確認します（肩の持ち上げも含む）。すべての部品は少なくとも 10 mm 離れている必要があります（サーボのギアのガタの余裕。safe_path.json の clearMm とリグの余裕で設定可能）。衝突する目標ポーズは、まず近くの空いたポーズを探し、次に RRT* で迂回路を探し、角を丸めた後にもう一度確認とタイミング調整をします。プレビュー、プロジェクト、書き出したコマンドは、確認済みの同じポーズ集合を使います。「音楽に合わせる」は、ロボットが追いつけないときに動きの幅を小さくすることがあります。オフにするとポーズを保ち、時間を足して動くか迂回し、プレビュー映像もロボットのペースまで遅くなります。ポーズが繰り返されても、音楽の時間が縮んだり巻き戻ったりしません。

3D 表示の品質は、ページを開く端末に合わせて自動で選ばれます。ハブ → 設定 → 3D 表示で変更できます。節約モードはフレーム数と解像度を下げますが、再生のタイミングと衝突チェックは同じです。エッジはページを読み込み直すと新しい値になります。

6 カクつかないなめらかな動き（止まらずにキーフレームを通過）
設定方法： 操作は不要です。Studio の動作セット、動画から作った動作、Studio が見つけた迂回ルート、話すときの動作、RL の動作、Shows など、すべての動作に自動で適用されます。関節が同じ方向に動き続ける場合、アームは各キーフレームで止まらず、そのまま通過します。関節が逆方向に動き始める箇所（振り払う動作）、一時停止（hold）がある箇所、動作の最初と最後では、キーフレームの位置で正確に止まります。どの動作もタイミングは変わらないので、音楽との同期も保たれます。ファイル内で、動作の作成元ごとにオン・オフを切り替えられます motion_smooth.json (sources) Studio の外部で作成されたモーションファイル（RL など）が使用する python tools/smooth_sequence.py ไฟล์.yaml スムージング処理によって動作が従来よりぎこちなくなることは決してありません。各キーで一時停止するよりカーブの揺れが大きくなるキーフレームは、自動的に速度が抑えられます（jerkGuard）毎秒 50 回の詳細な動きから圧縮された RL モーションでは、アームは元の動作速度で各キーを通過し、衝突チェック済みの元の軌道を維持します（followDensePath)
ロボットに起こること： 書き出したファイルには、次の行が含まれます pass: モーション前（その動作の開始速度と終了速度）。新ファームウェアを書き込んだロボットはこれをコマンドとして受け取ります PASS 旧型ロボットはこの行をスキップして従来通り動作します（各キーで一時停止）。Studio は同じ安全マージンを用いて、スムージング後の軌道上で衝突チェックを行います。カーブによって衝突が発生する場合は、チェック済みの直線軌道に沿ってキー位置で一時停止する動作にフォールバックします。ロボット自身も二重チェックを行い、サーボの許容速度を超えたり時間が引き延ばされた場合は従来通り動作します。4組のチアダンス動作では、途中の停止回数が 226〜429 回から 35〜101 回へと大幅に減少しました（実機での検証は未実施）。
7 元に戻す / やり直し（押し間違えても作品は消えません）
設定方法： タイムバー（ズームボタンの横）の ↶ Undo、または Ctrl+Z で、直前の変更（たとえば間違えて消したキーフレーム）を取り消せます。↷ Redo または Ctrl+Y で元に戻します。何段階でもさかのぼれます。ドラッグや入力を続けた操作は1段階にまとめます。ファイルやショーを開くと履歴は新しくなります。
ロボットに起こること： ロボットは変わりません。画面上のタイムラインのポーズだけが戻ります。すでにロボットへ保存した場合は、もう一度保存してください。
8 画面の色を変える（ダークモード）
設定方法： Studio の上部バーにある色の選択ボックスから配色を選びます。Midnight がダークモードで、長時間の作業でも目が疲れにくくなります。3D 表示の背景色も一緒に変わります。Hub の他のページと同じ配色なので、どこで選んでもすべてのページに反映されます。
ロボットに起こること： ロボットや動きのファイルは変わりません。このパソコンの画面の色だけが変わります。
9 同じ名前は上書き前に確認（2つのタブで上書きし合わない）
設定方法： Save を押すと、Studio はその名前がすでに使われていないかを Hub に確認します。別のタブや別の人が直前に同じ名前で保存していた場合は、置き換えるかどうかを尋ねるウィンドウが出ます。キャンセルして新しい名前を付ければ、両方のファイルを残せます。
ロボットに起こること： ロボットは変わりません。キャンセルすれば、元のファイルはそのまま残ります。
10 ほとんど人が映っていない動画（言葉で伝える）
設定方法： Make moves のあと、動画の4分の1未満でしか人が見えない場合、Studio はまず「この動画ではほとんど人が見えませんでした」と伝え、腕を含む全身が映る動画を勧めます。細かい数字（短い反転、不確かな瞬間）は Show technical details の中にあります。
ロボットに起こること： ロボットは変わりません。動きをタイムバーに置く前の判断を助けるメッセージです。
11 会場ネットワーク内の動画リンク(例: NAS)
設定方法： インターネットのリンクと選んだファイルは通常どおり使えます。ネットワーク上のデバイス(NASや別のPC)へのリンクは、安全のため最初は拒否されます。1) ロボットタブでログインします。2) そのデバイスの動画リンクを「またはリンク」に貼り付けて取得を押します。3)「ネットワーク上のデバイスです」と出たら「このデバイスを許可」を押します。4) もう一度取得を押します。一覧の確認や取り消しは、リンク欄の下の「動画を提供できる自分のネットワーク上のデバイス」を開きます。名前やアドレス(例: nas.local または 192.168.1.50)を自分で入力することも、削除を押すこともできます。このPC自身とクラウドのアドレスは常に拒否され、許可できません。
ロボットに起こること： ロボットは変わりません。ハブがどのデバイスから動画を取得するかを選ぶだけです。一覧はこのPCにだけ保存されます。

ロボットのポーズ学習画像（PC 上の実験）

ポーズの各方向からの画像を作るには、次を使います： python -m tools.robot_pose synth --n 20000 --no-images --out ABSOLUTE_PRIVATE_PATH、続いてレンダリング python -m tools.robot_pose.render_mujoco ABSOLUTE_PRIVATE_PATH/views.jsonl --out ABSOLUTE_PRIVATE_PATH。MuJoCo は Studio のリグと保存済みのカメラ設定を使い、光、色、テクスチャ、ぼかし、ノイズをランダムに変えます。ラベルでは、奥行き情報をもとに、ほかのパーツに隠れているキーポイントを示します。関節の中心がその関節自身のケース内にある場合は、リグの大きさに応じた許容幅で判定します。画像、ラベル、レポートはすべて PC 内の非公開の保存先に置いてください： .local/robot_pose フォルダー（省略しない完全なパスを使用）。これらはシミュレーション画像です。実際の動画にラベルを付けるには、静止姿勢を別途観察し、映像を目視で確認する必要があります。非公開のメッシュデータがあれば、CAD の外観も使えます。共通の関節構造に従い、元データの取り付け位置のずれも確認します。仮想の基点を含め、CAD に存在しない基準点にはラベルを付けません。学習用の画像には、少なくとも3つの関節が見えている必要があります。全体が隠れた画像は除外します。ラベルのない基点でも、ロボットの支柱の範囲を決めるために使えます。このツールから学習、カメラ撮影、ロボットへのコマンド送信は行いません。

記録した静止フレームの場合は、 python -m tools.robot_pose.lab_labels ABSOLUTE_MANIFEST.json --out ABSOLUTE_PRIVATE_DATASET 別途測定した関節の中心位置と、確認済みの静止姿勢からカメラの設定値を推定します。非公開の設定一覧では、動きが落ち着いた時間帯、確認済みの基準点、ロボットの範囲、動画単位での学習用・検証用データの分け方、実際に観察した姿勢の採用条件を指定します。コマンドへの応答だけでは、ロボットが指定の姿勢に到達したとは判断できません。動いているフレームや、姿勢が明らかに違うフレームは除外します。ラベルを付けるのは確認済みの基準点だけです。学習前に、目印を重ねたフレームを少なくとも 50 枚確認してください。1つの平面内に収まる姿勢が1つあるだけでは、実寸に基づくカメラの補正はできません。

未保存の作業を復元するとき、Studio は音楽の準備ができるまで再生や保存を待ちます。音楽を復元できない場合は、ダウンロードした .nong.json ファイルをもう一度開いてください。動きは画面に残ります。

選んだ作品のファイルは mice_system の中の results フォルダーにあります。results/index.html か、ハブのホーム → 最新の作品を開いてください。動きと音楽つきのファイルは results/bundles にあります。デスクトップのアイコンは自動では作られません。
