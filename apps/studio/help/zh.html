打开最新作品，包含动作和音乐

中心主页有应用 最新作品 用于已安装的作品。还没有列表的电脑可以直接导入文件。在 Nong Studio 中按 打开带音乐的作品 然后选择片段或文件 .nong.json 它将动作、骨骼绑定（rig）和音乐保存在单个文件中。系统在切换项目前会先读取并检查文件。如果有未保存的内容，会提示您先保存（Save）或取消，并让您选择是使用该项目的 rig 还是保留当前设置。更换 rig 可能会根据新的机械极限调整动作姿态或时间节奏。

按 带音乐试一试 即可在屏幕上配合原来的音乐查看动作。可以暂停、回到开头或拖动时间条。音乐是预览的时钟，所以标签页变慢时它也不会与动作脱节。如果音乐比动作先结束，剩下的部分是静音；循环时会在动作结束后重新开始音乐。打开作品或使用此预览不会向真实机器人发送任何命令。“在机器人上运行”按钮是单独的步骤。

保存 音乐也会保存在项目里，重新打开时仍然在，或者按 下载动作+音乐 将单个文件移到另一台电脑。草稿的音乐单独保存在浏览器里；如果该存储被关闭或清除，可能需要重新选择原文件，而恢复的动作仍然在。对于真实机器人，请使用 YAML 文件以及与 play: 命令同名的 MP3，放在 SD 卡上，按原有方式上传。系统不会自动上传或让机器人播放。

项目名称可以使用泰文和英文字母、数字、空格以及 _ - . ，但不能使用表情符号、/ \ :，也不能使用 Windows 保留的名称（如 con、nul、com1）。页面会用简单的话提示，已保存的内容不会被覆盖。

无法绘制 3D 的设备（电视、旧电脑，或关闭了显卡的浏览器）： Studio 仍然可以打开并使用。滑块、时间轴和在机器人上播放都正常，只是 3D 机器人画面会显示一条消息，说明这台设备无法绘制。要看到机器人，请用较新的浏览器或另一台电脑打开。

自动分离舞段： 默认的“自动”会自己检测新片段中的多个人物和镜头角度变化。使用“自动”或“群舞”时，系统每次都会比较整个片段中的动作，不会预先固定男/女的位置。手臂相同但腰部扭转或肩膀倾斜不同的人，可能被分进不同的舞段。选择“舞蹈编排”可查看每一段，或选择“分别保存舞段”，把证据持续不同、画面可靠、且达到默认设置所定画面比例的舞段另存为独立项目。“片段（Fragment）”是尚无法确认为新舞段的一段内容，可逐个查看和保存，不会每次镜头切换都算作新的舞段。如果新角度无法与之前的舞段清楚匹配，系统会结合舞者的外观和对所有组同时匹配，并在匹配仍不明确时标记“check cut”。仍不明确的新角度会保持原姿势，不会仅因时间过去就变得可靠。只有当该画面中看到的多个人确实做同一个姿势时，才会使用已确认的共享姿势。“% reliable”报告表示可用画面的比例，并不保证是同一个人。用户也可以选择自己手动指定人物。

无法匹配到同一个人的镜头切换： 系统会自动把它拆成多个场景片段，并选出在该舞段中连续出现的主要舞者，而不是随每个画面的置信度来回切换。每个部分的视频范围和动作时间对齐开始。修改视频范围时，会取消之前的读取并分析新的范围，不会在可见片段之前补上很长的静止站立。“生成并保存”会分别保存达到标准的舞段或片段，不会生成把不同动作猜成同一个人的演出。含糊的跨镜头匹配并不保证性别或同一个人。

连续舞蹈： 默认会保持姿势的形状，并根据机器人的限制增加时间。若想保持原来的音乐节奏，请选择“配合音乐”，这可能会减小运动幅度。系统会按时间过滤抖动，减少短暂的反向和关节角度的突变。当人在换姿势后静止不动时，机器人仍会运动到它在静止之前接受的姿势，不会因滤波而半途停下。开场姿势和静止片段会被保留，也不会把未来的姿势拉进来填补看不见的画面。滤波之后会再次检查碰撞和时间，并显示前后的反向次数。原始画面和误差报告仍用来检查滤波是否吃掉了太多姿势细节。骨架和电机的限位可能使某些姿势仍与真人不同。

跟随单人视频或群舞

比视频播放器最低速度还慢的绕行阶段，会按机器人的时钟一帧一帧地推进画面，同时声音暂停。用“同时播放”来停止或继续。更换视频或模式会立即恢复正常速度，并取消之前的读取。原始音乐不会被发送去绑定已被拉长时间的序列，因为节拍会错位；必须使用调整过时间的音乐文件。对于加油助威序列，会成对提供调整过时间的音乐文件。

在“视频”页面，可以分别把“表演者”选为“单个表演者”或“群舞”，把“镜头”选为“单一镜头”或“切换镜头 / 视角”。读取片段后，会出现可在“跟随”中选择的表演者编号。不同的舞段，例如男舞者和女舞者的，不会被平均在一起。请分别检查并以各自的名称保存每个人或每个舞段。

“转动腰部”使用躯干相对于髋部的角度，“跟随肩部倾斜”使用肩膀相对于躯干的角度，并与骨架中的真实机构对照。静止站立的人不会拉入未来的姿势来填补，也不会跨越镜头切换做平滑。侧面或俯视的摄像头在接受新姿势之前，会先在躯干坐标系内进行检查。

“学习型镜头检查”使用在模拟器中训练的 Q-learning 策略，帮助决定是接受姿势、保留旧姿势，还是补偿视角。在开启之前，会与几何方法做比较。如果人被遮挡、不确定是否是同一个人，或无法区分人的旋转与摄像头的旋转，就会保留最近一次可靠的姿势。模拟器的结果并不能证明在真实片段上的准确度。

按真实姿势检查手板、关节球、手臂杆、躯干和头部，包括耸肩抬升。每个部件之间必须至少相距 10 毫米（为舵机齿轮间隙留出余量；可在 safe_path.json 中以 clearMm 加上骨架的余量设置）。会发生碰撞的目标姿势会先寻找附近的无碰撞姿势，然后用 RRT* 寻找绕行路径，圆角处理之后再次检查碰撞和时间。预览、项目和导出的命令使用同一套已检查的姿势。当机器人跟不上时，“配合音乐”可能会减小运动幅度。关闭后，会保持姿势并增加时间去移动或绕行，预览视频也会放慢到机器人的节奏。重复的姿势不会压缩或倒回音乐的时间。

3D 画面质量会根据打开网页的设备自动选择。可在 中心 → 设置 → 3D 画面 中更改。节能模式会降低帧数和分辨率，同时保持相同的播放节奏和碰撞检测。重新加载页面后，边缘效果会采用新值。

机器人姿势训练图片（电脑上的实验）

生成姿势视图可使用 python -m tools.robot_pose synth --n 20000 --no-images --out ABSOLUTE_PRIVATE_PATH，然后渲染 python -m tools.robot_pose.render_mujoco ABSOLUTE_PRIVATE_PATH/views.jsonl --out ABSOLUTE_PRIVATE_PATH。MuJoCo 使用 Studio 的骨架和已保存的相机设置，并随机调整光照、颜色、纹理、模糊和噪点。标注会根据深度信息，标出被其他部件挡住的关键点。对于位于自身外壳内部的关节中心，会根据骨架尺寸留出判断余量。所有图片、标注和报告都应保存在 PC 的私有位置： .local/robot_pose 文件夹，使用完整路径。这些是模拟图像；真实视频的标注仍需要另行观察机器人保持静止的姿态，并人工检查画面。如果有私有的网格模型，也可以选用 CAD 外观；它使用同一套关节结构，并核对源模型中各部件的安装偏移。CAD 中不存在的参考点，包括虚拟底座点，都不会标注。用于训练的视角必须至少能看到三个关节；完全被遮挡的视角会被剔除。未标注的底座点仍可用来确定机器人立柱的范围。此工具不会启动训练、拍摄，也不会向机器人发送命令。

对于已录制的静止画面， python -m tools.robot_pose.lab_labels ABSOLUTE_MANIFEST.json --out ABSOLUTE_PRIVATE_DATASET 根据独立测量的关节中心位置和已知的静止姿态，估算相机参数。私有清单会指定机器人已停稳的时间段、验证过的参考点、机器人范围、按整个视频划分的训练集和验证集，以及实际观察后可接受的姿态。收到命令确认，并不代表机器人已经到达指定姿态：仍在移动或姿态明显不对的画面会被剔除。只有验证过的参考点才会标注。训练前，至少检查 50 帧叠加了标记的画面；仅凭一个平面内的单一姿态，无法完成基于实际尺寸的相机标定。

恢复未保存的作品时，Studio 会等音乐准备好后才播放或保存。如果无法恢复音乐，请重新打开已下载的 .nong.json 文件。动作仍保留在屏幕上。

选用的作品文件位于 mice_system 内的 results 文件夹。打开 results/index.html，或中心主页 → 最新作品。带动作和音乐的文件在 results/bundles 中。不会自动创建桌面图标。
