# hub

The hub program: one HTTP server (port 8642, plus 80 for the short name) that
reaches every board by USB, RS485 or WiFi, flashes them and plays shows.
`main_python/main.py` is being split into smaller files (A26-76 phase 2).

## Interface

- `/api/dev/<cmd|status|files|upload|download|delete>?dev=...` - the ONE way a
  page talks to a board. `dev` is `wifi:<ip>`, `usb:<COM>[:<bus id>]`,
  `hub:<ip>/<dev>` (a board on another PC) or `auto:<board key>` (fastest route).
- `dev_cmd(dev, line)` - the one way hub code sends a command.
- `modules_here()` - the one merged list: a board once, with every route to it.
- `hub_usb.py` - the USB serial manager (port table, per-port lock, reply
  reader), moved out of `main.py` 2026-09-21. main.py imports its names back.
- Checks that read the hub's source use `F.hub_src()` (main.py + every
  `hub_*.py`), so code can move between these files without breaking them.

## Rules and traps

- The hub is the ONE owner of every COM port (per-port lock, released after
  10 s idle). Nothing else may open a port while it runs.
- After changing any `main_python/*.py`, rebuild with
  `python -m PyInstaller --clean MiceHub.spec` - the spec, never a bare
  `--onefile` (that ships an exe with no pages and rewrites the spec).
- `main.py` is in `qc/data/scope.json` fullWhen: any edit runs the full gate.
- Checks assert on what reached the module (`fake_serial.wire`), never on what
  the page says about itself.
