# fw-core

Firmware every board runs: identity, the command router, RS485, USB serial,
WiFi and the board's web portal, SD, OTA, and `PERF?`.

## Interface

- Commands: `config/commands.json` (registry) and `COMMANDS.md` (reference) -
  both change in the same edit as the code.
- `CommandRouter::handle(line)` - every channel (USB, RS485, WiFi) ends here.
- `PERF?` - loop time, servo frame gap, who held the router lock, heap, stack,
  resets since power-on. `tools/bench_perf.py <port|ip>` drives every task.

## Rules and traps

- One command in, ONE reply line out, written in one call (`mice::writeOnce`).
  `Serial.println` splits it and a WiFi log line lands in the middle.
- `loop()` waits on the router lock before every servo frame. Anything slow
  under that lock freezes the arm; `PERF?` names the holder (`lock_by`).
- RS485: `send()` only queues; the `rs485tx` task calls `sendNow`, the only
  writer of Serial2. It waits with `uart_wait_tx_done` - `Serial2.flush()` is a
  busy spin in core 2.0.17 (116 ms stall measured) - then holds DE for
  `RS485_HOLD_US` (the NUL-byte corruption of 2026-08-20).
- Build every env: `pio run -e mice_nong -e mice_cam -e mice_lift -e mice_blank`.
  FastLED is pinned to 3.10.3: 3.10.5 pushed the lift past its OTA slot.
