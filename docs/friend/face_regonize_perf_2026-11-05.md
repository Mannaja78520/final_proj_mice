# ขอเพื่อนปรับ Face_Regonize ให้เร็วขึ้น/ประหยัดขึ้น (ความแม่นเท่าเดิม) — 2026-11-05

ที่มา: เราลองบีบ KV cache แบบที่ใช้กับ LLM (ตอนนี้ทำกับ Ollama ของเรา) แล้วตรวจว่าใช้กับ Face_Regonize ได้ไหม
อ่านโค้ดเพื่อนแบบอ่านอย่างเดียว (ไม่แก้ ไม่คัดลอกโค้ด) และวัดจากสคริปต์ของเราเองบน PC (RTX 5070 Ti, 60 รูป, 62 หน้า)
ข้อมูลดิบ: `.local/face_perf_2026-11-05/` บน PC (ไม่อยู่ใน git)

## สรุปสั้น
- **KV cache ใช้ไม่ได้** เพราะไม่ใช่ LLM เป็นโมเดล ONNX ขนาดเล็ก (det_10g 16 MB, w600k_r50 166 MB)
- ตอนนี้ **เร็วและเบาอยู่แล้ว**: ตรวจหน้า 6.1 ms + ทำ embedding 5.9 ms ต่อหน้า = ~12 ms ต่อรูป,
  VRAM ~0.56 GB ต่อเซสชัน (~1.1 GB ตอนมี live + background พร้อมกัน), RAM ~180 MB
  ที่ทำไว้ดีแล้ว: allowed_modules det+rec, det_size 320, ย่อรูปที่ 960px, จับคู่แบบ matrix (index.py:133), ข้ามเฟรม
- ไม่ใช่ปัญหาทรัพยากร ข้อด้านล่างเป็นของแถม ไม่บังคับ

## ขอ 3 ข้อ (ความแม่นเท่าเดิม เรียงตามผล)
1. **ทำ embedding แบบ batch** — `engine.py:460-461` วนเรียก `rec_model.get` ทีละหน้า
   วัด: 8 หน้า วนลูป 39.5 ms → batch 11.7 ms (เร็วขึ้น 3.4 เท่า) ช่วยเฉพาะรูปหมู่/หลายหน้า
2. **ย่อรูปตอน decode JPEG สำหรับรูปใหญ่ (~12 MP)** ใช้ `cv2.IMREAD_REDUCED_COLOR_2/4` แทน decode เต็มแล้วค่อยย่อ
   วัด: decode 33 ms → 17 ms (÷2) / 12 ms (÷4); ตอนย่อใช้ `INTER_LINEAR` แทน `INTER_AREA` 4.4 → 0.7 ms
   **ต้องเช็คก่อน**: จำนวนหน้าที่เจอต้องเท่าเดิมกับชุดรูปทดสอบของเพื่อน
3. **เร่งตอนเริ่มโปรแกรม** — insightface สร้าง session ของ onnx ทั้ง 5 ไฟล์แล้วทิ้ง 3 ไฟล์ที่ไม่ใช้
   ย้าย .onnx ที่ไม่ใช้ออกจากโฟลเดอร์ buffalo_l (ผลเฉพาะเวลาเปิดโปรแกรม)
