## Bugs found and fixed
1. **Windows device names** (`con`, `nul`, `com1`, `lpt9.txt`, trailing dot) were accepted as project names, so on the PC the save would hit the device, not a file. `main.py` `pc_name` / `safe_name` now refuse them. QC: `check_thai_names` (5 new cases; proven by breaking the fix: 5 fail, restored: pass). The old check sent no `project`, so it never reached the name test for valid names; the new cases send a full body.

2. **Save size**: `/api/save` now refuses bodies over 20 MB (was 100 MB shared ceiling; 60 MB was accepted). QC in `check_thai_names`.
3. **Video link into the PC/LAN**: links to localhost, private, link-local, `.local` addresses are refused in plain words (`hub_video._is_local_host`; QC check opts in with `allow_local`). QC in `check_video_page`, 6 cases.
4. **Help**: Studio help (th/en/zh/ja) now says which characters a project name may use. Both fixes proven by breaking them (8 cases fail, restored: pass).

## Found earlier, now fixed above (was: decision for the user)
* `/api/save` accepts a 60 MB body with no limit. Low risk (disk only), but a size cap would be wise.
* Fetching a video link only needs the scheme to be http/https; `http://127.0.0.1:...` is allowed (needs login, so only an admin can do it). The QC check uses a local server on purpose, so blocking loopback needs an opt-in switch. Left alone.
* Emoji in a project name is refused with plain words (Thai and Latin work). Fine, but Help does not say which characters are allowed.
* `/api/diag` takes ~9 s here (probes); fine for a support page, odd on a phone.
* NEVER_GATED (`/api/save`, `/api/export`, `/api/rigdefault`) is open on purpose (documented in hub_auth.py); HUB_API.md should say so next to "writes need login".
