# จากวิดีโอคนเต้น ถึงไฟล์ท่าเต้นของหุ่น (Nong) — algorithm ทุกขั้น

เขียนเมื่อ 2026-10-29 ตามที่ผู้ใช้ขอ: "ขอ algorithm ทำไว้ด้วยว่าที่ทำทำยังไงอะไรบ้าง"
ตัวเลขทุกตัวในเอกสารนี้มาจากไฟล์ config ที่ระบุไว้ ถ้าแก้ config ให้แก้เอกสารนี้ด้วย

ภาพรวม 9 ขั้น:

```
วิดีโอ ─1→ จุดตัวคน (30 FPS) ─2→ เลือกคนต้นแบบ ─3→ ทิศกระดูกแขน + เอว/ไหล่
      ─4→ เติมช่วงที่มองไม่เห็น ─5→ ปรับความสูงแขนให้อยู่ในระยะหุ่น
      ─6→ สร้างท่าหุ่น (RL / planner / แบบผสม) ─7→ ทำให้นุ่ม (smooth)
      ─8→ ตรวจการชน ─9→ ไฟล์ sequence สำหรับบอร์ด (+ เพลง)
```

ทุกขั้นใช้นาฬิกาเดียวกันคือ "เวลาในเพลง" (วินาทีที่ 0 = จุดเริ่มท่าแรกในวิดีโอ) จึงเทียบกันได้ตรงๆ

---

## ขั้น 1 — วัดจุดตัวคนจากวิดีโอ (pose extraction)

ไฟล์: `.local/cheer_rig_1029_30fps/extract_30fps.py` (ใช้ตัวตรวจจับของ `.local/cheer_rig_1027/extract_raw.py`)

1. อ่านวิดีโอต้นฉบับ (59.94 FPS) ทีละเฟรม เก็บทุกเฟรมที่ 2 → **29.97 FPS**
   (เดิม 6 FPS ทำให้ท่าสะบัดสั้นกว่า 0.2 s หายไป)
2. หาคนด้วย **YOLO11n-pose** (`imgsz` 960, `conf` 0.3, CPU) แล้วเลือกกล่องที่ใกล้ตำแหน่งแนวนอน 0.30 / 0.50 / 0.70 / 0.12 ของภาพ
3. ตัดภาพรอบแต่ละคน (ขยาย 25% ด้านข้าง 12% ด้านบนล่าง) แล้วหาจุดตัว 33 จุดด้วย **MediaPipe Pose Landmarker (full)**
   (`num_poses` 8, `min_pose_detection_confidence` 0.3, `min_pose_presence_confidence` 0.35)
4. ทิ้งคนที่ไหล่หรือสะโพกมองเห็นไม่ชัด (visibility ต่ำสุดของจุด 11, 12, 23, 24 ต่ำกว่า 0.45)
5. เก็บทั้งพิกัดบนภาพ และพิกัด 3 มิติ (world landmarks) ของทุกคน
6. ตรวจการตัดภาพ/กล้องขยับ: ความต่างของภาพย่อ 96×54 และการเลื่อนของพื้นหลังด้วย ORB + RANSAC (ไม่นับบริเวณที่มีคน)
7. เก็บลักษณะเฉพาะของแต่ละคนสำหรับขั้น 2:
   - histogram สีของ 4 แถบตัว (หัว คอ อก เอว)
   - เวกเตอร์ re-id จาก **OSNet x0.25** (ONNX)

เวลา: เพลง 168 s ใช้ประมาณ 16 นาทีบน CPU

## ขั้น 2 — ติดตามคนต้นแบบ (subject tracking)

ไฟล์: `retarget_30fps.cjs` เรียก `VideoSubjectTracker` ของ Studio (`nong/main_python_set_nong/web/app_parts/`)

- โหมด `group` (เต้นหลายคน) และ `cuts` (กล้องตัดภาพ)
- เลือกคนตามตำแหน่ง `anchorX`: center = 0.50, left = 0.13
- ข้ามการตัดภาพด้วยสีเสื้อ, re-id และตำแหน่ง ถ้าไม่แน่ใจ เฟรมนั้นจะถูกตั้งเป็น "ไม่เชื่อ" (untrusted)

## ขั้น 3 — ทิศกระดูกแขน และเอว/ไหล่ (fit)

`vidFitFrames` ของ Studio:
- ทิศ **ต้นแขน** (ไหล่ → ศอก) และ **แขนท่อนล่าง** (ศอก → ข้อมือ) เป็นเวกเตอร์หนึ่งหน่วย ในกรอบลำตัวของหุ่น (หักการบิดเอวออกแล้ว)
- **WAIST** มาจากการบิดของแนวสะโพกกับแนวไหล่ ส่วน **SHRUG** มาจากความเอียงของแนวไหล่
- IK ของ Studio ได้ท่า 10 ข้อต่อต่อหนึ่งตัวอย่าง (planner ใช้ค่านี้) แล้วผ่านตัวกรองของ Studio
  (`video_follow.json` smoothing: `windowMs` 350, `outlierDegrees` 12, `deadbandDegrees` 1.2, `maxTargetDps` 240, `maxTargetAccelDps2` 900)
- ทุกตัวอย่างมีธง `ok` บอกว่าแขนข้างนั้นเชื่อถือได้หรือไม่

ผล 30 FPS ของ Come and Cheer center: 4,751 ตัวอย่าง แขนที่เชื่อได้ 83.5% (ซ้าย) และ 78.0% (ขวา)

## ขั้น 4 — เติมช่วงที่มองไม่เห็นแขน (gap bridging)

ไฟล์: `tools/rl_compare/reference.py` `fill_gaps` — config `data.fillGapS` = **1.0 s**, `rl.fillWeight` = **0.5**

- ช่วงที่แขนไม่ถูกเชื่อติดกันไม่เกิน 1 s และมีจุดที่เชื่อได้ทั้งก่อนและหลัง ให้ผสมทิศจากสองข้างตามเวลา (linear แล้ว normalize)
- ช่วงที่ยาวกว่านั้น ให้ค้างทิศล่าสุดไว้
- RL ได้คะแนนจากช่วงที่เติมด้วยน้ำหนัก 0.5 เดิมได้น้ำหนัก 0 แขนจึงตกในช่วงนั้น
- คะแนนที่รายงาน (metrics) ยังนับเฉพาะจุดที่เชื่อได้

## ขั้น 5 — ปรับความสูงแขนให้อยู่ในระยะของหุ่น (reach fitting)

ไฟล์: `tools/rl_compare/reach.py` — config `reach`: `binDeg` 10, `samples` 300000, `dancerTopPct` 99, `kneeDeg` 0, `marginDeg` 5, `azWeight` 0.5

เหตุผล: ข้อไหล่ก้มเงย (SH_P) ใช้ servo 180° ผ่านเฟือง 14:19 จึงหมุนได้ประมาณ 132° (25–155°)
หุ่นจึงยกต้นแขนได้สูงสุดประมาณ 40° และยกได้เฉพาะไปทางด้านข้าง ผู้ใช้เลือกไม่แก้เฟือง
แต่ให้ยก "คล้ายคน" แทน

1. **หาระยะที่หุ่นยกได้**: สุ่มท่า 300,000 ท่าภายในขีดจำกัดข้อต่อ แบ่งทิศรอบตัวเป็นช่องละ 10° (azimuth)
   แล้วเก็บความสูงต้นแขนสูงสุดของแต่ละช่อง แยกแขนซ้ายและขวา
2. **ปรับความสูงตามสัดส่วน**: ใช้ค่าเปอร์เซ็นไทล์ที่ 99 ของความสูงแขนคนในเพลงเป็น "ยกสุดของคน"
   ความสูงที่เกิน 0° จะถูกย่อเป็นเส้นตรง ให้ "ยกสุดของคน" ตรงกับ "ยกสุดของหุ่น − 5°"
3. **เลือกทิศ**: ถ้าทิศที่คนยกเป็นทิศที่หุ่นยกไม่ขึ้น ให้เบนแขนไปทางที่ยกได้
   ต้นทุนของแต่ละทิศคือ `0.5 × องศาที่เบน + องศาความสูงที่ขาดไป` แล้วเลือกทิศที่ต้นทุนต่ำสุด
4. หมุนทั้งต้นแขนและแขนท่อนล่างไปพร้อมกัน (หมุนรอบแกนตั้งก่อน แล้วค่อยหมุนขึ้นหรือลง) มุมศอกจึงไม่เปลี่ยน
5. ท่าที่ต่ำกว่า 0° ไม่เปลี่ยน ยกเว้นทิศนั้นหุ่นทำไม่ได้เลย
6. เก็บท่าเดิมของคนไว้ใน `raw_bones` เพื่อใช้วัดผลเทียบกับคนจริง

ผล Come and Cheer center: ตอนคนยกแขน (เกิน 30°) ความสูงเฉลี่ยของคน 46° กลายเป็นท่าเป้าหมาย 25.5°
76% ของเฟรมเหล่านี้ยังยกเกิน 20° แขนเบนเฉลี่ย (median) 31° และท่าที่คนไม่ได้ยก เปลี่ยนเกิน 5° แค่ 10%

## ขั้น 6 — สร้างท่าของหุ่น

ทุกวิธีผ่าน **โมเดล servo** เดียวกัน (`tools/rl_compare/servo.py`): บอร์ดส่งเป้า 50 Hz,
servo ตามแบบ lag อันดับหนึ่ง 40 ms (ค่าประมาณ ยังไม่ได้วัด) และหมุนได้ไม่เกิน `servoMaxDps` ของ rig (375–400°/s)

### 6a. Planner (วิธีที่ Studio ใช้อยู่)
`tools/rl_compare/planner.cjs` เรียก `vidBuild` ของ Studio: เลือก keyframe จากท่า IK → ตรวจชน → เลี่ยงชนด้วย RRT
- `music: false` (planner_shape) รักษารูปท่า ถ้าเวลาไม่พอจะยืดเวลาออก ทำให้ช้ากว่าเพลง
- `music: true` (planner_music) รักษาเพลง ถ้าเวลาไม่พอจะตัดท่าให้สั้นลง
- เล่นบนนาฬิกาของบอร์ด (`tools/nong_sim/board_clock.py`): ทุกท่าเป็น cosine ease และหยุดที่ keyframe

### 6b. RL (imitation policy, PPO)
`tools/rl_compare/rl.py`, `env.py`, `ppo.py` — config `rl`
- ตัดสินใจ 25 ครั้งต่อวินาที (`controlHz`) ใช้หุ่นจำลอง 4096 ตัวพร้อมกันบน GPU (`envs`) แต่ละตอนยาว 4 s และเริ่มที่จุดสุ่มในเพลง
- สิ่งที่ policy เห็น: ท่าปัจจุบัน, คำสั่ง, ทิศกระดูกปัจจุบัน และท่าคนล่วงหน้า 0 / 0.2 / 0.4 / 0.8 s (`lookaheadS`)
- action: ขยับคำสั่งแต่ละข้อต่อได้ไม่เกินเพดานความเร็วของ scenario ต่อหนึ่งการตัดสินใจ
- รางวัล (`reward`):
  - ทิศกระดูก: น้ำหนัก 0.65, sigma 15°
  - เอว/ไหล่: น้ำหนัก 0.15, sigma 10°
  - ความนุ่มของ action: น้ำหนัก 0.2
  - ลงโทษเมื่อเข้าใกล้การชน (`nearMm`): น้ำหนัก 0.5
  - ลงโทษเมื่อชนขีดจำกัดข้อต่อ: น้ำหนัก 0.2
  - ถ้าชนจริง จบตอนนั้นทันที (`touchEnds`)
- โครงข่าย 256×256, PPO (`lr` 3e-4, `gamma` 0.97, `lam` 0.95, `clip` 0.2), 20 รอบ × 60 updates
- เวลาเทรน: ประมาณ 120 s/รอบ รวม 40 นาที (RTX 5070 Ti Laptop) เล่นทั้งเพลงใช้ 18 s

### 6c. แบบผสม (hybrid)
`run.py` `Case.hybrid` — config `hybrid`: `windowS` 0.5, `marginDeg` 5, `rampS` 0.3
- ใช้ RL เป็นหลัก ช่วงไหนที่ error เฉลี่ย 0.5 s ของ planner_music ต่ำกว่า RL เกิน 5° ให้ใช้ planner ช่วงนั้นแทน
- ค่อยๆ เปลี่ยนจากกันภายใน 0.3 s ท่าจึงไม่กระโดด (Come and Cheer center ใช้ planner 3% ของเพลง)

## ขั้น 7 — ทำให้นุ่ม (smoothing)

- **ใน sim** (`tools/rl_compare/smooth.py`, ตัวต้นแบบ): Savitzky–Golay แบบ zero-phase หน้าต่าง 0.24 s, order 3
  กับคำสั่ง 50 Hz จึงไม่ทำให้ช้ากว่าเพลง ผลคือ jerk ลด 59–66% และ error แทบเท่าเดิม
- **บนบอร์ด** (ตัวกลาง A54, `main_python/motion_smooth.py`, `tools/smooth_sequence.py`, `motion_smooth.json`):
  - ใส่ `pass:` ก่อน keyframe ที่ข้อต่อยังไปทิศเดิม ให้แขนผ่าน keyframe ด้วยความเร็ว (via speed) ไม่ต้องหยุด
  - แต่ละท่าเป็นเส้นโค้ง cubic Hermite (monotone ไม่เลยปลายทาง)
  - ยังหยุดเมื่อข้อต่อกลับทิศ (ท่าสะบัดจึงยังถึงจุดสูงสุด) หยุดตอน hold และที่ปลายเพลง
  - เวลาไม่เปลี่ยน
  - ค่าตั้ง: `velScale` 0.85, `maxOffLineDeg` 6, `uncheckedOffLineDeg` 1
  - ต้องใช้ firmware ที่มีคำสั่ง PASS

## ขั้น 8 — ตรวจการชน

ใช้สองตัวตรวจ ที่ระยะห่าง (gap) **5 mm** (scenario `servo_5mm`):
1. `kin.clearance` (`tools/rl_compare/kin.py`): ระยะผิวแบบประมาณระหว่างแขน มือ ลำตัว และหัว ใช้ใน RL และใช้ตรวจเร็วๆ
2. `StudioCollisionGeometry.hit` ของ Studio (`studio_eval.cjs`): ตัวตรวจเดียวกับที่ Studio ใช้ก่อนบันทึกท่า (มือเป็นกล่อง)
   ตรวจทุกเฟรมที่ 2 ของการเคลื่อนไหวจริงหลังผ่านโมเดล servo

ตรวจซ้ำอีกครั้งหลังแปลงเป็นไฟล์บอร์ด และหลังใส่ PASS (เล่นเส้นโค้งจริงทุกเฟรม 50 Hz)

## ขั้น 9 — ไฟล์ sequence สำหรับบอร์ด

ไฟล์: `tools/rl_compare/to_sequence.py` — config `sequence`: `tolDeg` 3, `minKeyMs` 120, `entryMs` 2000, `marginMm` 2, `refineRounds` 6, `perFile` 30, `maxFiles` 15

1. **ลดจำนวน keyframe**: ใช้ Ramer–Douglas–Peucker กับคำสั่ง 50 Hz ทั้ง 10 ข้อต่อ
   เก็บ keyframe เมื่อเส้นตรงระหว่าง keyframe ห่างจากท่าจริงเกิน 3° และ keyframe ต้องห่างกันอย่างน้อย 120 ms
2. ทุก keyframe เก็บเวลาของตัวเอง (`T` = ms จาก keyframe ก่อน) เวลาจึงตรงเพลง
3. ไฟล์ขึ้นต้นด้วย `pace: music N` (0 = จำกัดแค่ความเร็ว servo) → ท่าเริ่ม (`T` 2000) → `play: <เพลง>.mp3` → ท่าทั้งหมด
4. **เล่นจำลอง** แบบที่บอร์ดเล่น (BoardClock + โมเดล servo) แล้ววัดผลและตรวจชน
   ถ้าตรงไหนใกล้เกิน `gap + 2 mm` หรือ Studio เตือน ให้เพิ่ม keyframe กลางท่าที่บอร์ดกำลังเล่นตรงนั้น แล้วเล่นใหม่ (สูงสุด 6 รอบ)
   ถ้ายังชนอยู่ จะไม่เขียนไฟล์
5. **แบ่งไฟล์**: เมื่อ 2026-10-28 ไฟล์ขนาด 30 KB ทำให้บอร์ดค้างตอนสั่ง MOVE และบอร์ดตามไฟล์ต่อกันได้สูงสุด 16 ไฟล์ (`MAX_CHAIN`)
   จึงแบ่งเป็น 15 ไฟล์ต่อกันด้วย `next:` และทุกไฟล์ขึ้นต้นด้วย `pace` เดิม
6. **ค่อยๆ เพิ่มความเร็วในแลป**: ทำ 3 ชุดที่เพดาน 120 / 240 / 0 (เต็ม servo) เฉพาะชุด 0 เท่านั้นที่ตรงเพลง
7. เพลง: ตัดเสียงจากวิดีโอต้นฉบับ เริ่มตรงกับท่าแรก (`from` ของ analysis) ใส่ใน `/music/` ส่วนไฟล์ท่าใส่ใน `/moves/`

## ตัววัดผล (`tools/rl_compare/metrics.py`)

| ตัววัด | ความหมาย |
|---|---|
| `boneMusicDeg` | มุมต่างเฉลี่ยของทิศกระดูก ณ เวลาเดียวกันในเพลง เทียบกับท่าเป้าหมาย (หลังขั้น 4–5) |
| `rawMusicDeg` | ค่าเดียวกัน แต่เทียบกับท่าคนจริงก่อนขั้น 5 |
| `liftCorr` | correlation ของความสูงต้นแขนคนกับหุ่นตลอดเพลง (1 = ยกขึ้นและลงพร้อมกันพอดี) ไม่สนมุมตรงเป๊ะ |
| `boneShapeDeg` | มุมต่างหลังจับเวลาให้ตรงกันด้วย DTW (ดูแค่รูปท่า ไม่สนเวลา) |
| `driftEndS` | หุ่นช้ากว่าเพลงกี่วินาทีตอนจบ |
| `jerkRms` | RMS ของอนุพันธ์อันดับ 3 ของมุม servo (ยิ่งต่ำยิ่งนุ่ม) |
| `minGapMmApprox`, Studio flags | ระยะใกล้สุด และจำนวนเฟรมที่ตัวตรวจของ Studio เตือน |

ผลการทดลองทั้งหมดอยู่ที่ `docs/experiments/experiment-records.md`

python -m tools.rl_compare.to_sequence --dance come_and_cheer_center_30fps --data-dir .local/cheer_rig_1029_30fps --out .local/rl_compare_30fps_reach --contender hybrid --prefix cr
